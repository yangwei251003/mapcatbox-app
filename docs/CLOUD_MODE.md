公开 Pages 为静态导出的离线合成演示，不运行数据库、后台任务、认证服务、真实位置或云函数。默认不创建 Supabase 客户端、不提交凭据、不读取原私人配置。原代码中曾有硬编码连接配置，公开版已移除；原配置不随仓库或日志发布。维护者应在自己的服务控制台轮换曾硬编码的凭据，本仓库不代登录操作。

## 如需自己部署云版本

仅在自己隔离的新 Supabase 测试项目操作，先阅读全部 SQL 与 Supabase 官方认证/RLS文档；这些源码不是已经过真实后端验收的部署方案。不要使用原私人项目、真实好友/位置/账户资料或 service-role key。前端 anon key 是客户端公开标识，权限必须由服务端政策约束。

1. 安装 Node24、`npm ci`。复制 `.env.example` 到被忽略的 `.env.local`，自己填新项目 URL 与 anon key，并将 `NEXT_PUBLIC_CLOUD_MODE=true`。`NEXT_PUBLIC_ALLOW_DEVICE_LOCATION` 继续保持false，直到完成独立权限与隐私测试。
2. 数据库原设计包含11张表、RLS与交互RPC。先在隔离数据库运行 `001_schema.sql`、`002_functions.sql`、`003_seed_stray_cats.sql`、`004_privacy_guard.sql`。003仅合成数学点，不是现实地点，不应放入真实地图。`all-in-one.sql` 是同一组内容的便利副本，二者只能选一种，不能重复执行。
3. 可选手动迁移器默认只显示说明，不连接网络。必须自己提供私有 `DATABASE_URL`，再明确运行 `node scripts/run-migrations.js --apply-to-new-empty-database`；拒绝非空publicschema、校验证书、整文件执行、事务失败回滚，不记录连接值。此次只验证了其无参数拒绝路径，**没有执行迁移或连接数据库**。
4. 手动验证注册、登录/注销、RLS跨用户隔离、好友双向确认、通知更新、RPC、并发、配额、错误恢复和数据删除后，再考虑真实数据。原代码的领养按钮仍是提示；设置/好友详情/互动记录页面未完成；猫粮数量/服务定时衰减/Realtime端到端未验收。SQL存在不等于功能可用或安全证明。
5. 若明确需要设备位置，重新设置定位开关并构建。在地图点击“明确开启位置共享”，确认后才调用watchPosition并写自己配置的库；真实浏览器还会询问位置权限。客户端最多每30秒尝试一次、禁止并发写入；失败也限流。停止共享、离开地图、隐身或注销会停止监听，并等待正在进行的写入结束后尝试删除自己的位置行。网络中断/关闭进程可能阻止删除，仍须设计服务端TTL和删除核对，不能依赖客户端保证清除。

004限制资料读取为本人/公开资料/已接受好友可见资料，好友位置读取尊重隐身，互动记录仅本人猫咪可写；同时撤下原允许任意参与方写accepted的宽泛好友策略，改为请求者只能发pending、收件人确认/拒绝、参与人可撤销，并禁止更新时替换双方身份。未连接PostgreSQL验证，不能把规则文本当实测合格。上线前仍需全面权限与安全审计；客户端限流并不能约束恶意客户端，服务器也应设置速率/保留期限。旧项目的既有好友记录也要单独核对，不能认为修改策略会追溯确认旧关系。
